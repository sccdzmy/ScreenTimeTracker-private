# Local security hardening

The application is intended for one local user. The server listens on `127.0.0.1:5124`; network sharing and remote server addresses are unsupported.

## Login and extension pairing

Open the interface from the desktop application or tray. It supplies a one-use fragment credential valid for 60 seconds. The interface removes the fragment before redeeming it for a 12-hour HttpOnly, SameSite=Strict session. Restarting the server invalidates sessions. Reopen the interface to renew an expired session.

In Settings, generate a pairing code and paste it into the browser extension's options within five minutes. Codes are single-use. After upgrading from the original extension, pair once. Each extension receives a separate credential restricted to website reporting and metadata; server storage contains hashes only. Settings can revoke all extension credentials.

Production APIs require authentication. Session mutations additionally require an exact Origin and CSRF credential. Extension requests are limited to 10 per second per credential. Login and pairing redemption are limited to five requests per minute. Development allows only `http://127.0.0.1:5173` with credentials; Swagger is development-only.

Firefox uses the MV2 `browserAction` API fallback. Firefox 140 or later is required. Its manifest declares browsing activity and website metadata/image collection, following the [Mozilla data consent documentation](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/). Reports contain a host, a bounded site name, and duration; they do not send full page URLs, query strings, or page text to the backend. Favicons are fetched only from the active page's origin, without credentials or redirects.

## Files and resource limits

- APIs accept server-issued `iconId` values, never filesystem paths or configurable icon directories. Image URLs authenticate with the session cookie.
- Custom PNG/JPEG/ICO content is decoded and re-encoded as PNG. Inputs and output are at most 2 MiB; dimensions are at most 4096×4096. ICO frames share a bounded pixel budget. Arbitrary SVG and HTML are rejected; shipped category SVGs remain trusted.
- Managed filenames are generated by the server in `Data/ManagedIcons`. Reads, writes, export and import cleanup reject directory traversal and reparse points. Clearing an icon removes its database reference; shared content-addressed files remain, so another record is not broken.
- Migration preserves usage records and copies validated icons from the original known local icon directories. Unsafe references, outside custom directories, and invalid images fall back to placeholders. Migration never deletes original or outside files.
- Website reports require valid hosts/ports, names of at most 256 characters, and durations of 1–5000 ms. Accumulation is limited by server report intervals; idle and suspended reports do not contribute. The queue holds at most 256 reports and returns HTTP 429 when full.
- Hour and timeline queries cover at most 31 days; daily summaries and rankings cover at most 3660 days. Rankings accept 1–1000 items.
- Imports accept at most 64 MiB and 100,000 sessions. Structures, values, icons and intervals are validated before writes. Writes use a database transaction. Failed transactions remove only files they created. Ordered interval indexes avoid quadratic overlap checks. Valid v1–v4 formats remain supported.
- Chart HTML tooltips escape names and validate CSS colors. CSP, nosniff, frame restrictions and no-referrer headers apply; API responses are not cached. Error responses omit stack traces and physical file paths. UI launch failures do not log fragment credentials.

## Dependencies and remaining advisory

NuGet auditing covers transitive dependencies and no longer hides NU1903 warnings. Central versions and lock files pin the resolved graph. SQLite native assets, OpenAPI and npm dependency overrides were upgraded; final Windows publication includes .NET 10.0.12. SkiaSharp validates raster images without introducing an ImageSharp license requirement.

`security/dependency-audit.json` records a local comparison against the public [GitHub Advisory Database](https://github.com/github/advisory-database); `security/artifact-audit.json` records runtime inventories. No private dependency graph needs to be uploaded. The audit script intentionally returns a nonzero exit status while any finding remains.

One development dependency remains affected: `node-forge` 1.4.0, [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv). The announcement has no patched version. Its path is `web-ext → @devicefarmer/adbkit → node-forge`; adbkit TCP/USB Android authentication calls the affected RSA verification code. That Android debugging path is outside the desktop build and runtime workflow. The package is absent from the generated frontend, Chrome/Firefox extension scripts and Windows application outputs. Do not use this dependency graph for Android TCP/USB debugging. The finding is retained, not suppressed; upgrading or replacing the Android tooling remains pending an upstream fix. This does not establish that every undisclosed or native-code vulnerability has been ruled out.

## Verification

See `security/verification.md` for commands and measured results. Tests use temporary SQLite databases, mock collection state and fictional websites/processes. Browser UI tests use isolated Chrome and Firefox sessions. They do not install the extensions into personal browser profiles or collect actual usage history.

Native Photino/tray behavior, real Windows idle/suspend signals, and installed extensions across actual browser upgrades still require manual integration checks. Browser UI and mocked extension tests are not substitutes for those checks. Reparse protection assumes the local account does not deliberately race filesystem changes; the application does not defend against administrator or same-account malware. Usage data is local and not encrypted at rest. Per-request limits are enforced, but there is no total icon-storage quota.

## Source-control privacy

Database files, runtime data, logs, exports, browser captures, dumps, secrets, local licensing files and generated artifacts are excluded. Tests contain only fictional data. New commits use a generic contributor identity and engineering descriptions. Existing upstream history is retained.
